稳定空间继续采用 `JSON.stringify([platform, videoId, partId])`，B 站为 BV＋cid，标题与 URL 的 P 序号不作为主键。活动页面另有 Chrome tabId/documentId 和后台维护的 epoch；刷新、Chrome 顶层 history 导航、同 URL 返回及媒体变化使旧绑定失效。观察串行处理；每次读取完成重新观察，旧绑定／旧重试结果不提交到新视图。epoch 首次以本轮时间戳开始，使 Worker 重建后重新取得会话；不持久保存原字幕或会话缓存。

observer 只在 ISOLATED 发送无业务数据的观察提示。后台验证 Chrome sender.id/tab/frame/document/url，只触发从 Chrome 重新观察，不接受提示中的身份或任何存储目标。页面没有 postMessage 到扩展的桥接。ApplicationClient 仍仅可信 sidepanel/reader 顶层可调用；reader 查询固定空间，不抓原字幕，所有写与定位命令拒绝。参考 [Chrome scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting)、[permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions)、[webNavigation](https://developer.chrome.com/docs/extensions/reference/api/webNavigation)。

W2-T02-FIX-01 最小返修：URL／初始 metadata 与明确播放器 cid 一致后才形成实时绑定；player 或 cid 未知／错配时保持未就绪，定位入口也独立拒绝，完成后再次核验。当前播放器没有旧 getVideoMessage；getManifest 返回 BV/cid，mediaElement 指向实际 video，getMediaInfo.playUrl 给出当前播放源。现代接口要求身份、元素、readyState≥1（seek 缓冲时无需已有未来帧）及独立的播放源关联，不能只按新 manifest 放行旧解码器。旧明确 getVideoMessage 身份仍兼容。

W2-T02-FIX-02：QA 的 P3/cid62131 正常 m4s 文件不含 cid 前缀。保留已验证的数字 cid 前缀路径；无前缀源需匹配明确属于该 BV/cid 的播放响应中的视频 URL。首次文档采用服务器 inline `window.__playinfo__` JSON（仅解析、不执行），按 Navigation Timing 的原始 BV/P URL 与 pages 映射关联，不能使用随 SPA 更新的 root cid/p 或把当前 URL 关联到旧响应。SPA 采用资源计时中站点已生成、BV/cid 匹配的 `/x/player/wbi/playurl` 请求，有界3秒、include/no-store/redirect-error 重取；不自行签 WBI。只比较 DASH video／durl 的 HTTPS bilivideo 子域 origin＋完整 pathname，允许签名 query 更新，不用音频、文件名特例或 CDN 视频正文。

确认的路径与 BV/cid 关联仅留在当前 MAIN 文档内，最多32条，避免站点清资源计时后同媒体失去依据；它们仍是不可信站点输入，不是 Chrome 权限、document/epoch binding 或存储目标。已知跨 cid 的同路径视为歧义并拒绝；无初始关联、无匹配请求／响应、坏响应和未知源仍未就绪。异步取证前后复核 URL/pages、player 对象、manifest、video 元素、currentSrc、playUrl 和 readyState。FIX-03 将定位写入移至 ISOLATED，MAIN 只提供媒体证据；具体异步边界见下文。已开始的 seek 不能撤销，只能拒绝把换源后的结果报告为成功。无需新增权限、依赖、数据库或客户端契约。

这些接口／HTML 格式属于本轮实测站点协议，不是官方稳定保证。无法取得现成播放响应的未知格式不默认放行，后续协议变化需重新验证。签名 URL、完整播放响应、原字幕和视频正文不进入日志／报告／持久层；本文不放行截图或后续功能。

保留同 tab 最后确认的 localSource 作为本地空间访问目标，与 live source/binding 分开；暂时检测失败、导航过渡和撤权清空实时能力但不隐藏已确认草稿。明确确认新媒体后才切换本地目标；不同 tab/window 不共享该回退，tab 移除释放。localSource 仅 Worker 内存，不进入持久层或客户端 DTO。

permission-denied 保留原状态契约：无 binding 表示当前没有 host 权限／有效媒体能力，提供原生授权；有 binding 表示已经过 host 权限检查后服务 metadata/CDN 拒绝，标注“字幕服务拒绝读取，可重试”，提供绑定准确的 video.retry。重试重新核对实际权限和绑定；撤权后失效，不绕过授权。非 JSON 403 仍按 HTTP 状态识别，不落入无字幕。没有新增权限、依赖或数据库迁移。

W2-T02-FIX-03：取证开始即复制 BV、选中 cid、pages 原始字段和播放器身份，不跨 await 保留可变站点对象作为比较基准。取证前后的所有媒体检查及最终 live 身份检查完成后，才提交路径关联；失败观察不向缓存写关联。缓存依旧只是可再验证的站点证据。

定位采用局部两阶段流程。观察先从 ISOLATED 获取当前文档的导航 revision，再由 MAIN 异步读取媒体证据；revision 纳入 Worker 会话签名。命令先核对 Worker binding/marker，然后在精确 documentId 的 ISOLATED 保存单次使用的 video 引用、currentSrc、URL 和 revision；MAIN 完成异步取证后，Worker 再同步核对当前 binding/marker。随后 ISOLATED 最终提交检查其原生导航 revision、媒体引用／源／readyState；MAIN 的一次性 DOM 事件回调仅同步复核所选 cid、manifest、playUrl 等媒体信息，不执行写入。事件没有 binding、时间、字幕或业务 DTO；页面不能靠触发／取消该事件发起定位，也不能覆盖 ISOLATED 生命周期。该 MAIN 确认仍属不可信媒体证据，不替代 Worker 或 ISOLATED 能力检查。最终确认及原生 currentTime 写入之间没有 await。

ISOLATED 的 Navigation currententrychange 覆盖同文档 push/replace/traverse，pagehide/pageshow 也使 revision 失效；即使 Chrome 的 Worker 导航事件还在传输，A→B→A 仍会取消已准备的定位。参见 [Chrome Navigation API](https://developer.chrome.com/docs/web-platform/navigation-api)。媒体 emptied/loadstart 取消本次准备；并发的新命令替代旧准备，每份准备最多15秒、单次消费，完成后清理监听。清晰度恰在准备期间切换可能拒绝该次命令，下一次观察／新命令可重新取证恢复；正常新源响应不会被永久禁用。缺少 Navigation API 的浏览器明确失败，当前实测 Chrome 版本另列报告；未声称旧版本实机通过。

写入已开始后的导航仍返回 stale-binding，但不能撤销已发生写入；回归分别断言“失效后才发起”为0次新增原生写入，以及“已发起后失效”为已发生1次并报告 stale。VideoPort、公开错误码、权限、存储、字幕生命周期均不改变；新增函数仅在 video 模块内部。

## 2026-10-19：播放期间的身份稳定性与已完成字幕复用

同文档 history state、追踪参数、时间和评论 hash 的变化不构成视频/P 变化，不能重建字幕会话。ISOLATED 媒体 revision 仍区分真实 BV/P 切换及页面生命周期；任何历史事件都取消待执行的单次媒体写入。

字幕 payload 和 live binding 分开：短暂失去身份时收回 live binding；每标签页最多保留一个已完成 payload，重新证明同 document/BV/cid 后可以恢复。明确导航、权限变化或手动刷新不能用该记录跳过新读取。

隐藏播放器接口的兜底来源证明可以由 Worker 复用，但必须同时匹配 document、route marker、ISOLATED revision、mediaRevision、currentSrc。不得把 MAIN 页内缓存当作这项证明，也不得让其他视频的预取请求替代当前解码器。详见 `docs/reports/playback-subtitle-loop-2026-10-19.md`。

## 2026-10-19：持续观察不能饿死已有请求（0.1.19）

Chrome 观察和 VideoSessions 两层队列均按轮次合并；一个已有调用最多等待下一次串行检查，后来的播放通知不能延长该调用的等待。禁止通过「一直检查到没有新通知」来结束共享 Promise，否则连续播放会同时卡住查询、字幕读取后的复核和手动重试。观察失败仍允许下一轮执行，真实导航的 revision 与旧结果拒绝规则不变。

只读 MAIN 身份取证前后比较同 origin、规范化视频路径和 P；时间/hash/追踪参数变化不撤销同媒体识别。带 binding 的写命令仍保留完整 URL 检查及 ISOLATED 最终提交边界。0.1.18 生产包在持续播放通知下的失败对照、0.1.19 五轮重复测试与登录实站结果见 `docs/reports/connection-starvation-2026-10-19.md`。

## 2026-10-20：Peer CDN 播放地址兼容（0.1.20）

实站目标视频使用 `*.edge.mountaintoys.cn:4483`，播放响应同时列出 `*.mcdn.bilivideo.cn`。识别接受这两个实测 HTTPS 域名族和播放器已选择的 TLS 端口，但必须由当前 BV/cid 的 inline 或既有 API 播放响应独立关联完整视频路径，不能仅凭 cid 文件名前缀通过。只检查播放地址，不下载视频或新增访问权限；所有文档、路由、解码器、异步前后及定位保护不变。0.1.19 失败对照与最终 0.1.20 登录实站 13 条字幕结果见 `docs/reports/peer-cdn-subtitles-2026-10-20.md`。
