# T12/T13 AI 字幕与主字幕契约

`contracts/subtitles.ts` 定义 SubtitleVersion、AnalysisSource、SubtitlesView。数据库仍为 v5；复用 subtitleVersions，workspace 兼容新增 subtitleVersionIds、analysisSource、analysisSourceRevision，不迁移、不清库。AI 版本属于长期资料。新版本不可变，包含语言、translate/enhance 类型、生成时间、来源 ID/指纹、来源语言、exact 对齐及 AI cues；原生正文不写入 jobs/workspace/版本中的来源字段。

`ApplicationClient.subtitles` 是可选兼容接口：query 指定空间／可选固定版本；source.select 按 sourceRevision 乐观并发修改。数据库字段仍名为 `analysisSource`，只作为旧数据兼容；产品概念统一为“主字幕”。主字幕可以是当前空间内任一有效保存版或某个原生语言轨，其他空间、删除、结构失效均 source-changed，不自动回落原始。invalidate(workspaceId, versionId) 是 T19 最小复用口：保留不可变行并标 deleted，保留已选 ID 为失效状态；用户必须显式选另一版本／native。旧请求的来源 ID、指纹、历史快照继续保留；重试无法获取原版本时失败。

字幕工作台只有一个主字幕选择，它同时控制时间轴显示、Chat／Markdown 上下文、AI 翻译和 AI 字幕修正的输入。同空间各 Chat 共享该选择。发送 Chat／Markdown 时，taskService 解析主字幕，freezeChat 在事务内重新验证归属与当前选择，冻结兼容字段 analysisSource(versionId/fingerprint 或原始 locator/fingerprint)。保存版由已保存正文供给，原生源不可用也可执行；retry 只用旧 snapshot/basis，不重读当前主字幕选择。

0.1.46 的字幕主选择位于顶部标题栏，设置选择器同步同一来源。选择回执与查询按作用域、请求序号和来源修订号处理；旧响应／旧错误不得覆盖新来源。写入回执未到达时禁用其他来源写入与 AI 发送。字幕列表在工作台内独立滚动；设置为固定浮层，不参与列表布局，任务记录自 0.1.52 起收进设置中的折叠区。默认跟随开启，手动翻看暂缓跟随；「刷新并跟随」恢复读取与定位。播放订阅临时读取失败时自动退避恢复，旧绑定失效或订阅关闭后停止；跳转沿用 preserve 策略，整行字幕均可触发。

0.1.52 起，AI 翻译在字幕列表上方仅显示当前操作的临时反馈。进度直接读取任务 coverage，完成必须为真实 completed 终态；“查看译文”只关联同 jobId 和 attemptId 的有效翻译版本，复用主字幕选择命令，成功切换后立即收起提示。切换失败保留反馈和错误，不假定已经切换。完成提示在无人交互时保留 5 秒，再用 220ms 淡出并收起布局；停止、失败及中断提示为 8 秒，重试入口也保存在设置内。指针停留、键盘焦点、命令或来源写入期间暂停超时，减少动态效果偏好下不做视觉过渡。刷新或重新进入时只恢复仍在执行的任务，不根据历史译文恢复完成通知；保存的译文始终可在字幕设置中选为主字幕。底部不再常驻任务状态，任务明细及 AI 指令入口移入字幕设置的“字幕任务记录”折叠区。见临时反馈报告（历史内部记录，未纳入公开源码：`../reports/subtitle-translation-notice-0.1.52-2026-10-22.md`）。

`generation.subtitle.send` 固定 target(workspaceId/operation)、默认 modelId、翻译目标语言和主字幕来源(binding 或 sourceVersionId)。界面不再暴露模型、处理要求或另一套来源选择。AI 翻译只要求目标语言；AI 字幕修正无需额外参数。不要求 Chat，不读取 Chat 历史／草稿／模板／引用，不添加消息。沿用 freezeSubtitle、原宿主、claim/checkpoint/finish、SSE ProviderPort 和现有 Key 路径；每空间一个字幕执行槽，其余排队，与 Chat 槽独立，全局仍 2 个执行标签／10 个未结束任务。按 jobId 停止；任务始终提交原空间，切视频不改归属。

`run-subtitle.ts` 逐段 JSON 处理，每批最多 40 cues／4000 字符、最多 16 批，每批一次服务调用，不做摘要／自动重试。翻译返回完整对齐 cues；修正先利用批内前后语境，只返回高置信 ASR 同音／近音／断词／漏字错误及识别错误的专有名词、人名 `{index, content}`，本地验证索引并合并原文，从而减少输出 token。纯标点、空格和大小写变化会被本地过滤，不进入保存版；不扩写、概括、语法润色或纠正说话者事实。单 cue 或总批数超限在接受前拒绝；任意缺段、错序、越界、重复索引、断流或输出截断均失败，不保存部分版本。输出累计最多 100000 字符。

只有完整成功 finish 同一事务提交版本、空间关联、终态和完成凭证。持久 basis 额外保存时间 SHA-256（没有正文／时间数组），提交时再次核对段数、次序及时间指纹；终态重复或取消／完成竞争不重复保存。检查点仅保存覆盖与空 text，处理中的原生／中间结果只留内存。

已有译文独立显示；原生不可用时明确要求重新读取后才能显示原生双语，绝不保存原文副本。复用 T11 NativeSubtitles / 纯 SubtitleTimeline。固定 `reader.html?workspaceId=…&subtitleVersionId=…` 仅查 URL 固定保存版，无 Chat／草稿、VideoPort 调用、播放订阅或定位；请求层限制为 workspace.query/subtitles.query，拒写／拒跨对象。T17 未实现不影响此独立 Reader。

验证入口：单测 t12-subtitles / t13-analysis-source；`node tests/installed/t12-t13-http.mjs` 使用真实应用／IDB／执行器／HTTP SSE、测试构建 VideoPort 和外部模型协议替身、synthetic Key、独立 profile。复用 T05 生命周期及 T11 实站轨道／播放器证据，未改变解析与播放算法。真实模型翻译质量、结构化输出稳定性和付费分段 not-run；生产无本机权限／测试标识，模型 API 调用 0。

## 0.1.57–0.1.58 字幕流程 v2

界面新建字幕任务冻结 `subtitleWorkflow:2`，依次执行全文专名预检、可选的实际联网核名、全文术语裁决、分批纠错／翻译及译后／纠错冲突复核。同一实体只有一个确认写法；不能裁决的纠错冲突回到原始表达，不发布互相矛盾的猜测。术语扫描按 150000 字符分片，处理批次最多 160 条／12000 字符，整段支持 100000 条／4000000 个正文字符和 4096 批。旧快照保留原有 40 条／4000 字符分批和处理协议。

0.1.58 修复术语裁决的别名校验：新确认的 canonical／target 可以出现在自己的 variants 内，但每项必须关联输入中已有候选，不得引入无关别名或多重归属。支持 R 等单字母官方名称。

`subtitle-response.ts` 统一 v2 的响应解析。只移除完整包裹 JSON 的代码围栏，不从解释文字中提取片段，不拼补缺失 JSON。结构／对齐校验失败时只对当前阶段或批次修复一次，保留最初输入与上一条响应；第二次仍无效则失败。认证、网络、限流、服务截断、输出预算与取消不自动重试。翻译条数、顺序、时间，及修正的索引归属、唯一性均继续严格校验；没有完整结果就不写入字幕版本。完成的修正版沿用翻译的临时通知，只有点击查看或在设置内选择才切换主字幕。

## 0.1.59 实际失败响应修复

用户提供的 deepseek-flash 响应把领英、OpenAI、豆包、混元、快手和 IBM 等已正确名称返回为 `variants:[]`，0.1.58 的 `min(1)` 因此拒绝整个术语阶段。现在术语预检、全文复核和译后术语检查统一接受空列表；预检按本批原文／译文中实际出现的 canonical 或 variants 筛选和去重，正确名称也进入上下文。复核仍要求 canonical 或变体关联已有候选，拒绝无关别名及同一变体多重归属。有效空列表不会触发额外修复请求。

局部协议修复现在附带受限字段路径和错误类别，区分 JSON 语法、字段类型、纠错索引和翻译对齐问题，不复制原文到错误提示；仍仅修复一次。固定规则 v29 明确空列表的含义与来源要求。

“千万”等纯数字／数词形态的 ASR 变体保留在 glossary 中，由分批模型按句子判断，不再进行全文字面替换。纠错输出若把原文明确数量中的该变体机械替换为产品名，会只恢复该数量，保留同句其他修正；翻译不做此中文数量恢复。此保护不代表能自动裁决所有普通词与专名的同形歧义。

## 0.1.60 保守纠错替代全文规范化

纠错的目标是恢复有充分依据的 ASR 错词，保留原话的重复、赘词、语法、简称、昵称、截断和自我纠正；不推断补词，不纠正说话者的定义或事实，不把合法中文名／英文名互换。固定规则 v30 同时约束术语预检、术语裁决、分批纠错和新增的必要性复核。翻译的术语处理维持原有契约。

v2 纠错取消分批前和保存前的 glossary 全文替换；批次输入始终是未改写原文。模型的整句候选先与原文比较，提取局部替换；纯增删、纯标点／大小写调整和纯中英文字转换不进入复核。对混合候选分离删除的重复和错词替换，不能以批准错词为由删掉邻近口语。差异计算有界，过大的差异保留原文。

`subtitle-correction-review` 接收原文邻近语境、核名证据和局部 edits，只允许返回已有 edit.id 的 `approved` 数组；不能生成新正文。每组最多 240 个 edits，按 48000 字符目标分组。重复、外来 id 或额外正文都按协议失败，仅允许当前组的一次结构修复。全部成功后，只把批准的局部替换应用到原句，其余文字、条目和时间逐字保留；失败不保存部分版本。实际 ASR 错拼的语义判别仍依赖模型，不能用程序过滤证明其全部正确。

验证：581 项单测、12 项生产包浏览器回归通过。811 条历史付费响应回放和 481 条混合修改夹具验证原句保留、完整保存及手动切换；新增复核阶段使用明确的受控响应。前次授权的 10 次真实 API 调用已用完，本版本新增真实调用为 0，未声称新的复核模型质量已经实测。详见纠错策略报告（历史内部记录，未纳入公开源码：`../reports/subtitle-conservative-0.1.60-2026-10-23.md`）。

## 0.1.62 字幕显示与自动归位

双语时间轴分别使用主字号和辅助字号；主字号沿用原偏好键，辅助字号新增 `vcamp.subtitleAuxiliaryFontSize`，缺省 14px，均在 14–24px 范围独立保存。`vcamp.subtitleAutoReturn` 缺省为 true，旁边保留原「跟随播放」开关。跟随开启时，手动滚动暂缓定位；自动归位开启时，从最后一次滚动起计时 5000ms，随后定位到最新播放位置。继续滚动会重新计时，关闭开关、关闭跟随、切换视频或卸载列表均清理计时器；关闭自动归位后可以一直手动翻看。

刷新图标移到标题栏字幕设置旁，tooltip 说明重新读取并定位，沿用既有 `video.retry`；刷新恢复跟随，不更换已选择的保存版主字幕。设置只保留来源、双语、字号、跟随、自动归位、任务入口及必要结果和错误，删除例行处理说明。两项新显示偏好和全局 HTML 风格选择均参与便携备份恢复。详见界面更新验证报告（历史内部记录，未纳入公开源码：`../reports/composer-display-0.1.62-2026-10-23.md`）。
