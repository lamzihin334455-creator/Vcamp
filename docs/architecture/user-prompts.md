# Vcamp 用户可配置提示词

实施日期：2026-10-20。基于固定规则目录 `2026-10-20.v2`，本阶段保持固定规则正文与选择机制不变。

## 管理和组合

角色是表达偏好，模板是任务要求，两者独立存储和选择。内置内容是可编辑的起点，不属于产品固定规则。

| 对象 | 字段 | 作用范围 | 入口 |
| --- | --- | --- | --- |
| 角色 | 名称、描述、完整角色指令 | 当前对话，发送后继续保留；新对话默认不选角色 | 设置 → 角色设置；输入区角色选择器与管理入口 |
| 任务模板 | 名称、描述、完整任务要求、产物类型、可选默认模型 | 当前请求，发送后退出模板 | 设置 → 模板工作流；输入区 @ 菜单 |

两者都支持查看、编辑、创建、复制、删除。复制先打开独立的副本表单，用户保存后创建新对象。删除前有行内确认；从列表移除，同时保留历史版本和已有选择。对话中的保留角色版本仍可使用，也可以切换为默认表达；模板可以退出或重新选择。

角色提供老教授、小学老师、可爱伙伴、网络串子四个起点。模板复用现有 Chat、Markdown、HTML 预设。选中内置模板后，输入框也允许补充要求；选择模板保留已输入文字。输出类型仍随模板确定，用户通过编辑或选择其他模板更换产物，模型仍可手动切换。

角色与模板的完整文本可在输入区展开查看。管理页保存会产生新版本；当前草稿保留原选定版本，用户重新选择后才使用新版。这些入口不构成完整 API 指令预览。

## 2026-10-22 表达偏好更新

角色不仅是人格或口吻，也管理叙事方式、回答详略、组织习惯及时间点的显示频率和形式。偏好通过“角色指令与表达偏好”自由文本填写；列表简介是说明信息，不作为表达指令。未配置的偏好由模型按任务决定。

任务目标与产物格式仍受当前任务约束；表达偏好按“本次明确要求 > 当前角色 > 模板默认值”处理。每轮最终回答加载同一简短时间协议，保证格式与导航能力，不强制出现时间点。v25 增加明确的区间示例后，纯字幕 Chat 系统文本为 1150 字符，审计基线为 1403 字符；字符数不等于 token 数。

新增内置快速总结/知识笔记 v2 默认值，保留原 v1 的解析与备份兼容。角色和模板仍按版本冻结，修改后重新选择生效。最终请求把本次明确要求放在模板与角色之后；辅助资料规划不再给最终生成传入额外输出要求。以下原始设计记录中将角色仅描述为口吻的部分，以本节为准。

## 数据和 API

- 复用模板的版本设计：独立的 `roles`、`roleRevisions` 表，角色选择 `{ roleId, revisionId }` 保存在草稿中；旧草稿缺少该字段时使用默认表达。
- 模板继续使用 `templates`、`templateRevisions`。编辑内置项时创建本地覆盖版本，保留内置历史版本；列表按 ID 合并，不出现重复项。
- 保存与删除都检查预期版本，拒绝过期窗口的覆盖。删除标记留在实体上，版本记录不删除，确保已选草稿、已发请求和重试仍可解析。
- 发送在原事务中解析角色版本，冻结到 `roleSnapshot`，同时冻结模板与其他上下文。重试使用原快照；角色编辑或删除不改变它。
- 最终调用的 system 仍仅包含产品维护的 P0/P1；当前用户消息携带标为 P3 的角色指令、P2 当前要求和模板。固定优先级继续规定当前任务高于角色表达。
- 历史角色快照用于记录和备份，不重新注入为本轮角色。新选择只作用于之后的新请求。角色不进入字幕纠错、翻译、资料规划、取帧规划或网页检索调用。
- 不增加模型调用轮次，不新增变量语法，不改变 Provider、队列、输出解析和 HTML 隔离方式。角色正文最多4000字符，计入原12000字符当前任务总预算；当前输入与模板仍受原8000字符合计上限约束。

## 迁移和备份

数据库升级为 v9，仅增加两个角色表，原表和记录不改写。备份升级为格式5、数据库版本9，包含角色、角色版本、草稿选择、消息和任务快照；继续读取格式1–4。

角色和模板均进行版本关系校验。导入冲突时成组复制并重映射引用；内置项导入为普通用户副本。已删除项也保留依赖，避免备份恢复后丢失历史配置。格式5应使用本版或后续兼容版本恢复，旧插件不能读取新增格式。

## 明确取舍

1. 角色按对话持久化，避免切到其他视频或新对话时意外沿用人格。跨对话默认角色可在后续作为单独偏好讨论。
2. 选择固定到具体版本，保存不自动更新其他草稿。代价是用户修改后需要重新选择；收益是不会悄悄改变准备发送的任务。
3. 删除是从可选列表移除，历史版本仍会占用少量存储，并随备份保留。本阶段没有历史版本清理或回收站界面。
4. 用户可自由编写文本指令；遵从性依赖模型，程序继续通过现有解析器、运行环境和数据校验保证必要的技术约束。本阶段的模拟 API 测试不代表真实模型质量评估。

## 验证结果

- 全量单测：55个文件，328项通过，1项既有失败。新增7项角色测试覆盖独立存储、内置编辑、版本冲突、删除后旧版保留、三种产物的 P2/P3 组合、重试、备份关系、旧格式迁移和读写权限。
- 唯一失败为 `opt-permissions-cover.test.ts:32`：测试将仅浏览的空间当作最近资料，但现有资料库成员规则只包含已保存成果。用原 v8 数据库入口复测同样失败；此次没有更改该业务或测试。
- 5项浏览器回归通过：新角色/模板管理与实际发送链路、模板笔记取帧、已授权空计划回退、无字幕代表帧回答、拼音模板选择。新链路验证固定 system 不含用户文本、P3 不进入资料规划、模板与角色组合、刷新后保留选择及切回默认表达。
- 360px 窄栏截图检查后修正了模板指令展开时的标题挤压，并通过浏览器宽度断言复核。
- `npm run typecheck`、`npm run build` 和差异空白检查通过。构建保留已有主 UI chunk 超过500kB提示。
- 全部 API 验证使用模拟服务，未调用真实模型；真实模型对角色、任务冲突和长视频生成质量的遵从性仍需单独评估。
