# Vcamp 提示词体系：设计原则与第一步实现

日期：2026-10-20；表达偏好更新于 2026-10-22，预算更新于 2026-10-23。当前规则版本 `2026-10-23.v26`。角色现管理语气、叙事方式、回答详略、组织习惯及时间引用偏好，以下分工以本次更新为准。

0.1.54 的 HTML 预算规则从用途策略读取65536 token／100000字符上限，去除固定24000字符精简目标，要求按任务保留必要内容、依据和交互，并预留完整闭合空间。预算不决定输出篇幅，不覆盖角色的表达偏好。

## 已确定的原则

| 优先级 | 所属组 | 责任 | 冲突处理 |
| --- | --- | --- | --- |
| P0 | 产品固定规则 | 产品定位、真实能力、事实与资料边界、优先级 | 不允许角色、模板或资料覆盖 |
| P1 | 产品固定规则 | 当前功能必需的输出协议、运行限制、数据对应关系 | 只在对应功能启用时加载；不能被 P2/P3 覆盖 |
| P2 | 用户可配置指令 | 当前任务目标、所选模板与内容重点 | 本次明确要求优先；模板中表达方式属于默认值 |
| P3 | 用户可配置指令 | 角色、口吻、叙事方式、详略、组织习惯、是否附时间及频率/形式 | 表达偏好按本次明确要求 > 当前角色 > 模板默认值处理；不改变任务目标、事实、能力与产物格式 |

角色与任务模板是独立设置。正式学习笔记配合幽默角色时，表达可以轻松，但笔记目标、必要结构和事实不变。字幕、引用笔记、图片、网页和历史回答是上下文资料，没有指令优先级。历史模板只描述过去的任务，本轮明确延续的要求才继续生效。

固定规则可以公开查看，其“固定”表示普通用户只读。每项规则具有稳定 ID、版本、优先级、标题、存在理由、生效条件和完整正文。密钥和认证信息不属于规则目录。用户修改模板不能为运行环境新增网络、存储、扩展 API 等能力；隔离和协议校验仍由现有代码实施，提示词不是安全机制的替代品。

## 2026-10-22 表达与阅读更新

最终消息按资料引用、任务模板、当前角色、本次明确要求排列；没有模板/角色/引用的纯问答直接发送原请求。辅助资料规划仅传入任务解读与资料选择，不再把规划生成的 `outputRequirements` 传给最终回答。原计划仍保存在任务记录里。

每轮 Chat、Markdown、HTML 最终回答共用 222 字符的 `time-links` 技术协议；内部规划与字幕处理不加载。协议规定有效来源、秒数精度、可点击格式和区间标签，并给出区间链接示例，不要求附时间。是否输出时间、频率及形式由角色自然语言偏好管理，本次明确要求优先。全局层没有新增“简答不附时间”之类的默认偏好。

快速总结和知识笔记升级为 v2 默认模板：取消固定五点和强制时间点/栏目。内置旧版继续可解析，用户修改、已选择版本与重试快照不被改写。角色设置仍使用原有自由文本字段，增加详略与时间呈现的填写示例；列表简介仅为元信息。

Chat/Markdown、HTML 预览与导出保留时间链接的区间和说明；仅纯单点文字规范化。HTML 不再通过覆盖 textContent 删除链接的强调子节点。Chat 的 H1/H2/H3 为 22/19/16px，Markdown 笔记仍为 22/18/16px。

0.1.51 补齐自然语言中未显式加链接的时间范围：Markdown 和 HTML 共用 `videoTimeParts`，支持句中、括号、表格、多行及常见区间分隔符，将起止两端分别转成可定位时间。已有链接与代码保持原样；无效或倒序区间不生成半个链接，超出视频时长的端点仍由原校验拒绝。普通单点继续仅在有上下文或行首等既有条件下识别。以用户原始评分回答作固定夹具，覆盖四组区间、八个端点及流式更新、HTML 导出回归。

## 第一阶段已完成的迁移（历史记录）

规则目录：[fixed-rules.ts](../../extension/src/prompts/fixed-rules.ts)。可直接阅读全部正文的导出：[fixed-prompt-catalogue.md](fixed-prompt-catalogue.md)。目录版本为 `2026-10-20.v2`。

`selectFixedRules(context)` 返回本次实际生效的只读规则及说明；`fixedPrompt(context)` 使用同一批内容构造 API 系统指令。展示与请求无需维护两份提示词。每项正文带稳定标识，如 `[P1:html-format]`。取帧时间范围和名额来自已校验的运行参数，不由用户模板填入。

| 旧位置/规则 | 迁移归属 | 本次处理 |
| --- | --- | --- |
| run-chat 的视频学习定位、通用事实边界 | P0 公共规则 | 合并为产品定位、优先级和资料边界，所有 AI 调用共享；优先级归属统一在 priority 中说明 |
| 回答中的多来源分类 | P1 source-attribution | 仅最终生成使用，按实际使用的来源区分；不强制增加栏目或 JSON 字段，不进入内部规划、字幕处理和网页检索 |
| Chat/Markdown 的时间跳转格式 | P1 time-links | 仅 Chat/Markdown 最终生成使用 |
| Markdown 输出格式 | P1 markdown-output | 仅 Markdown 最终生成使用 |
| HTML 文档、运行能力、窄栏要求 | P1 html-format / html-runtime / html-layout | 仅新 HTML 页面使用；验证器保留原实现，原导出名继续兼容 |
| 网页引用方式 | P1 web-citations | 最终请求实际获得网页资料时使用 |
| 无字幕/图片说明 | P1 vision-evidence | 无字幕任务或确实带图片时使用；不宣称拥有完整字幕 |
| 需求资料规划、取帧规划 | 各自 P1 协议 | 迁到目录，按调用选择；保留当前来源白名单和取帧行为 |
| 字幕纠错、字幕翻译 | 各自 P1 协议 | 保留索引、时间、忠实性和可解析 JSON；目标语言作为任务字段传入 |
| 联网一次搜索及来源要求 | P1 web-search | 从用户资料文本拆出到该接口的系统字段 |
| 旧知识 JSON 的字段和 basis 规则 | P1 legacy-knowledge | 独立保留，只供旧协议分支，不注入新 HTML |
| 回答优先800字、笔记优先1500字、统一精炼偏好 | 后续 P2/P3 配置范围 | 从全局固定指令移除，不暗中转换成新的固定默认值 |
| HTML 固定中文语言、固定字号和行高 | 后续内容/风格配置范围 | 文档语言随内容，保留窄栏可读、换行、焦点等宿主适配要求 |
| 视觉规划理由120字的偏好 | P1 实际字段边界 | 对齐现有 schema 的500字符上限；整体输出 token/字符预算不变 |

固定层不再规定章节数量、回答篇幅、人格或视觉风格。机器可解析结构、实际 token/字符预算、HTML 运行隔离、字幕对应关系属于必要技术约束。

## 本次请求组装

最终生成仍走现有 runChat、Provider、任务队列与保存流程，消息按以下顺序组装：

1. `system`：本次生效的 P0/P1 规则。
2. `user`：明确标为资料的当前视频上下文，包括标题、完整主字幕或无字幕状态、已选补充资料、规划结果、视觉取得情况和实际网页资料。
3. 已冻结的对话历史：保留消息角色，历史模板明确标为历史。
4. `user`：本次请求、P2 当前任务模板、用户引用及实际附件。

资料内容和用户模板不会被插入固定系统规则。内部规划仍按现有输入合同，只读取来源类型与当前任务信息。网页补充接口使用 `system` 承载固定规则，`messages` 承载用户任务和视频资料；该字段由 [DeepSeek Anthropic 兼容接口](https://api-docs.deepseek.com/guides/anthropic_api/)明确支持。

本次没有增加模型调用轮次，也没有改变端点、模型选择、任务队列、数据库或备份协议。原生字幕仍按现有生命周期处理。此次迁移会改变新执行请求的系统文本；当前持久化快照尚未固定历史提示词版本，不能宣称旧任务可重现原版系统文本或相同回答。

## 后续阶段的清楚边界

第二阶段已实现角色与模板的查看、文本编辑、创建、复制、删除和切换；两者独立存储、选择并在请求中冻结。角色按当前对话持久化，内置模板也开放编辑和本次补充要求。设计与取舍见 [user-prompts.md](user-prompts.md)。

第三阶段已接入“本次 AI 指令”界面：发送前查看配置和候选资料，发送后从真实网络请求记录查看各阶段规则、任务、角色、上下文和模型参数。记录按浏览器会话限额保留，不重建旧调用、不改写冻结记录。实现与保留边界见 [instruction-viewer.md](instruction-viewer.md)。

内置模板的输入锁定已在第二阶段解除。字幕 requirements 字段的消费、检索任务完整投影等仍按后续阶段逐项处理。本阶段专注于固定规则分类与迁移，不以同时重建设置界面和 API 工作流作为前提。

## 验证边界

新增请求组装和规则选择测试，检查 P0/P1 顺序、功能规则不串入其他任务、资料不进入 system、完整字幕/历史/引用不丢失、无字幕边界和取帧参数。沿用已有字幕 JSON、HTML 完整性、网页来源、冻结与图片测试。

这些检查证明程序选择和传递了正确规则、格式与数据，没有证明真实模型一定服从所有要求或内容质量已经提升。真实模型风格冲突与任务质量比较留在后续受控评估中。
