# T16 contract and reproduction

## W10 FRAME-01 — current candidate

One visible initialization now supports subsequent hidden captures on ordinary
headed Chrome 155.0.8059.39. Diagnostic reproduction observed seeked at 226 ms
but no rVFC before its 9425 ms timeout. rVFC is a compositor-presentation callback,
not a mandatory decoded-seek completion notification. The capture function now
requires this operation's seeking/seeked sequence, paused target position within
0.01 s, available current data, source/element identity and nontransparent canvas
pixels. It performs a fresh seek even for repeated time requests. See the
[HTML seeking algorithm](https://html.spec.whatwg.org/multipage/media.html#seeking)
and [rVFC definition](https://wicg.github.io/video-rvfc/). No background playback,
focus emulation, per-frame activation or new decoder is used.

Internal seek deadline is 9 s, outer injection deadline 12 s, total initialization
30 s. A bounded memory-only scalar trace records the stages; no source URLs,
credentials, subtitle bodies or persistent browser capability enter that trace.
Failure/cancellation fences the operation, removes listeners/callbacks and retires
the lease, preventing later captures from reusing a timed-out seek.

The actual React sidepanel has per-request authorization, pure-text bypass,
plan-first, and cancel/keep-draft exits. Global preference remains OFF by default.
Pure-text bypass disables autonomous planning/capture for this request; existing
explicit manual/history attachment rules still apply. The one-use session grant
binds original media, job/attempt, focused window/return tab, Worker incarnation,
focus history and a 30 s expiry. Worker restart cannot consume an old grant or
recreate automatic-return rights. Same-window initialization has one bounded slot.
User activation of an existing media copy revokes capture and cleanup ownership;
source/tab/window navigation or switching revokes return rights permanently.
Stop/delete invalidate return before asynchronous cancellation. Registry cleanup
covers unique pre-stamp staging documents and recovers after Worker restart.

Verification: one full six-grid passed through the real Side Panel consent UI,
with real H.264 pixels in final local HTTP requests and source operations preserved.
Local known-color sample passes visible 1/3/5/7 and hidden 1/3/5/7/3/3; colors were
independently decoded by FFmpeg. An ordinary Bilibili P2 copy delivers hidden 1 s
and 5 s PNGs across source P3 navigation. Narrow continuation checks cover consent
cancel/pure-text, user switch without focus stealing, stop/delete, navigation and
user takeover, pre-stamp owner loss/Worker restart and explicit budget choices.
Initial harness failures (ordinary tab instead of Side Panel, stale Chat selection,
old-document reload race, overstrong interrupted-initialization expectation) are
recorded separately; the six successful grid cells are not rerun or relabelled.
Full historical regression results remain at their original commits.

From extension: `npx vite build --mode capture-test`, then
`node tests/manual/t16-ready.mjs` for real-site; `T16_FRAME_SAMPLE=1` selects the
local pixel regression. `node tests/installed/t16-http.mjs` runs the controlled
installation; `T16_BASIC_ONLY=1` skips the six-grid; `T16_CLEANUP_ONLY=1` plus
BASIC_ONLY selects lifecycle continuation; `T16_UI_ONLY=1` selects final consent
layout/cancel; `T16_READY_RESOURCES=1` selects pre-stamp/budget checks.
These scripts use raw CDP only for trusted UI/source control, never media-target,
Worker or executor attachment. Production excludes the test probe and localhost.
Real model planning/visual quality remains not-run; this candidate is not an
integration or release decision. Old focus-assisted results stay ineligible.

## Historical inactive-route contract (prior to W10)

Status: **blocked; not candidate-ready**. The installed production port creates a
muted inactive original-site tab. In raw headless Chrome 149 without focus emulation this never-seen tab can
defer media loading/decoding, so the port reports `host-timeout` rather than READY.
Neither source-player seeking nor activating the media tab is an accepted fallback.

The global switch defaults OFF. Each accepted send freezes its actual setting,
model, subtitle basis, history and manual attachments. Explicit request permission
is held only in `chrome.storage.session`, consumed once by the original-media
port, and cannot be reconstructed from an imported backup. Preauthorization tries
to establish the lease **before** planning. A ready lease requires exact BV/cid,
document ownership and drawable decoded pixels. Planning uses the existing
ProviderPort and complete subtitle segmentation. Its strict time-only plan is
limited by T15's six-image count/byte budgets, duration and duplicate checks.

Persistent `attempt.visual` records only plan, phase, original-request attachment
IDs and explicit images/subtitle choice. Images are added atomically to the active
attempt, never a mutable draft. The final stage freezes before the answer request.
A retry reuses a fully frozen stage; an incomplete stage receives no old grant.
Backup v8 accepts the optional fields; it carries no executor, lease or grant.
The executor has a ten-minute lifetime and one media host; existing TaskService
admission bounds executors. Readiness is bounded by 30 seconds, individual media
operations by 12 seconds. Disposal checks exact URL/document/isolated-world token;
a navigated tab is preserved. Stop/delete invalidate the attempt before cleanup.

## READY-01 follow-up

The installed desktop Chrome 155.0.8059.39 also fails readiness with the source
tab active in a focused normal window: the inactive muted host stays hidden,
readyState=0, decoded frames=0 for the bounded 30 seconds. The same installed
binary in headless mode gives the same result. `tests/manual/t16-ready.mjs` uses
raw CDP pipes and `Extensions.loadUnpacked`; Playwright never connects. It records
arguments, target attachments, window/tab/DOM/media states and the exact failure.
Run it from `extension/` with Node; `T16_HEADLESS=1` selects the single control.
`T16_NATIVE_DIAGNOSTIC=1` adds an explicitly diagnostic data-URL native video to
the owned site tab (not the source); that also remains undecoded. It never counts
as original-media acceptance. Ordinary readiness must pass before the grid runs.

Chromium's [media load deferrer](https://raw.githubusercontent.com/chromium/chromium/main/components/no_state_prefetch/renderer/no_state_prefetch_utils.cc)
waits for visibility for hidden pages without previous playback (with a documented
Document PiP exception). The observed native/data-URL stall supports this browser
gate over a Bilibili-only lazy-init or network hypothesis. This upstream reference
is not a claim that the installed binary was rebuilt from that exact source.

Creation is now owned by a Worker handler, using a unique blank staging URL and
session-only `vcamp.mediaPending.*` registration before navigation. Exact trusted
executor URL/tab and one-use binding grant are required. Owner removal/navigation
and Worker startup reconcile the record; cleanup verifies the staging URL or the
recorded site document. User-navigation revokes cleanup. Executor-side decoded
readiness and isolated ownership checks are unchanged. No new permission/DB schema.
Source inspection is bounded to 12 seconds; staging commit wait is bounded to two
seconds. No heartbeat or permanent page is added.

`T16_READY_RESOURCES=1 node tests/installed/t16-http.mjs` runs only the direct
resource checks: server-held navigation before the first ownership stamp, Worker
restart then executor destruction, preserve a user-navigated host, and five actual
manual frames plus a two-frame plan requiring explicit subtitle or stop. This
passes with no focus emulation and no media-ready success claim. The pre-fix build
fails the owned-tab disposal assertion. It is intentionally separate from six-grid
acceptance and uses the existing bundled Chrome 149 headless resource harness.

Remaining decision: keep the inactive-never-shown site-tab constraint and T16
blocked, or explicitly revise the product behavior to allow one visible media
bootstrap (focus interruption), or a separate user-visible PiP media window with
new lifecycle work. Neither exception is implemented or acceptance-tested here.
An extension-owned decoder would instead require a separate media acquisition /
authentication design. Longer timeouts and page `play()` retries do not bypass the
observed browser gate.
