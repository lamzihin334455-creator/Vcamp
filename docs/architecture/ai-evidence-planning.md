# AI 证据规划协议（v1）

## 固定原则

- 视频标题、当前分 P 身份和完整主字幕是每次视频理解请求的核心依据。
- 需求规划调用只接收数据类型、本次请求、产物类型和模板要求，不接收标题、字幕、简介、章节、评论或历史正文。
- 用户主动引用的笔记和图片不由规划器决定，仍按用户选择强制冻结。
- 字幕超过最终请求上限时明确失败，不以摘要静默替代全文。
- web 必须同时具备服务能力和当前对话明确开启的联网开关。模型、模板 requiredSources 和回退规划均不能授权；冻结请求仍以草稿开关为准。

## 发送流程

1. 校验当前视频、主字幕、模型和草稿版本。
2. 读取 B 站公开元数据，建立可用类型列表。
3. 需求规划器从 `video_chapters`、`video_description`、`hot_comments`、`conversation_history` 中选择最少的补充类型。
4. 插件校验白名单并拉取被选中的正文。
5. 冻结需求名单、实际取得的补充资料、标题、历史、引用和字幕身份。
6. 最终模型收到标题、完整字幕、冻结补充资料和用户请求。

规划失败时回退为标题、完整字幕、用户主动引用，以及存在时的问答历史。高热评论始终标记为观众观点，不能作为视频事实。

## B 站来源

- 视频简介和视频身份：`/x/web-interface/view`
- 站内时间章节：`/x/player/v2` 的 `view_points`
- 高热度评论：`/x/v2/reply`，最多 20 条，去重并限制单条长度

请求不携带登录凭据。远端字段都按不可信资料处理，不能改变系统规则、权限或产物类型。

## 旧协议

旧自由 HTML 和 `knowledge-json-v1` 不再出现在新建或引用选择中，也不能发起新任务。旧成果、备份和已冻结任务保留只读与重试兼容，避免直接删除解析器导致历史资料损坏。
